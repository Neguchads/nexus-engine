# Real-provider benchmark evidence protocol

Run from the checkout: python -m benchmarks.evaluate records.json

The evaluator accepts a list of paired records. Identity fields: task, class (simple/medium/complex), repeat, host, model, config_sha256, initial_sha256, prompt_sha256, budget. Measurement fields: mode (direct/nexus), passed (bool from independent verifier), latency_ms, input_tokens, output_tokens, recovered (bool). Hashes are lowercase SHA-256. Both arms must share the same identity. Use an independent pristine checkout for each arm, randomize order, preserve failures and specify verifier and interruption scenario in an external preregistration.

At least ten distinct tasks with three repetitions per class are required for the minimum sample. The report compares pass counts, recovery counts, median latency and total reported tokens per arm. It does not certify performance, attest to a model, validate underlying raw logs, or automatically approve a release. If actual usage is unavailable, do not fabricate a record. Record and investigate budget violations separately; this evaluator rejects them. No external records are included in this repository.

## Controlled real local experiment

Run python -m benchmarks.live_ollama --profile pilot --output NEW_DIRECTORY against an already-running local Ollama and qwen2.5-coder:0.5b. The pinned GitHub workflow downloads the official runtime, verifies its SHA-256, checks the published model digest prefix and records the full observed digest. The pilot runs six pairs, the full profile 90. Both arms use the same task and model, but deliberately differ in context: full synthetic context vs explicit code-field projection. Nexus measures its local journal and reopens it to verify accounting; the source checkpoint is known preexisting data, not an inference call. The expected integer is computed independently without executing model output. Failures and unknown usage are retained. The preregistered experimental gate requires all transport/accounting observations valid, a nonzero baseline pass count, no regression in total correct answers, and at least 20% reported input-token reduction. This is a narrow controlled code-reasoning experiment, not a representative engineering benchmark. Full profile does not by itself satisfy production acceptance. Model card: https://ollama.com/library/qwen2.5-coder:0.5b (Apache 2.0 model). Runtime: https://github.com/ollama/ollama/releases/tag/v0.40.18.

### Initial pilot and independent replication

The 0.5B pilot [run 45704542157](https://github.com/Neguchads/nexus-engine/actions/runs/45704542157) completed 12 real calls with no transport errors, but **failed** the preregistered quality gate: direct 0/6 correct, Nexus 2/6 correct, 3,048 vs 566 reported input tokens (81.43% reduction). It is retained as negative evidence, not superseded. The next pilot uses the separately selected 7B model (https://ollama.com/library/qwen2.5-coder:7b, published digest prefix dae161e27b0e), identical dataset, order seeds and acceptance gate. No changes to the tasks or scoring; no model mixing in an individual comparison.

### Three-arm repair-selection pilot (pre-registered)

Nine distinct checked-in function repair tasks, three per complexity label. The model chooses a candidate identifier; the verifier executes only trusted repository functions against independent expected inputs/outputs. No model-generated code execution. The three arms use the same model and instruction: full context, direct projected context, and Nexus projected context. The projected arms must have identical Ollama request-body SHA-256. The gate requires all calls with valid accounting, at least 6/9 Nexus correct, no aggregate correctness regression versus either control, and at least 20% fewer reported input tokens than full context. This pilot deliberately includes irrelevant release history and is not an autonomous repository-repair evaluation. A matching projected direct control can explain the context reduction without attributing it exclusively to orchestration. All failures are retained.

## Historical source repair pilot (pre-registered)

Three related, real historical JSON-identity defects in the alpha 6 Store at commit 25cb48b5ea45b8ac05fdcf0f4a018641d835f97d: completion equality, request binding and dependency binding. The model proposes a bounded comparison expression; a strict AST grammar allows only operand references, comparisons, boolean operations, encode and type. Trusted code substitutes historical operands and writes a separate source copy. Independent subprocess regression verifies each patch, with a failing unmodified control and a passing known-fix control. No arbitrary model code or changes to main. Three matched arms use the same model and instruction, full actual source context versus projected direct and projected Nexus. Gate: valid accounting, all 3 Nexus repairs pass, identical projected request bodies, no errors. Not representative autonomous engineering; defects are related and scope is intentionally limited. Preserve failures.
